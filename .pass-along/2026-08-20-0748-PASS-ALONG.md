## Decisions and rules

- **A local path is never a repo identity.** `REPO` holds `owner/name` from the origin remote or
  stays blank; the path goes in `WORKING_DIR`. Writing a path into `REPO` makes an unpushed
  scratch directory look clonable to a later reader.
- **Inference may only select a workspace-confirmed session.** A wrong `HARNESS`/`SESSION_ID`
  pair is worse than `unknown`, because the next reader trusts the document. Unverified
  candidates are surfaced but never promoted. Do not relax this back into a recency sort.
- **Check for a store migration before assuming a parse bug.** opencode's JSON tree still existed
  and still parsed — it was just frozen two dozen versions back. A harness reporting "no sessions"
  for a repo you know it worked in means suspect the layout first.
- **Separate what is vendor-documented from what was observed.** The homes and env overrides are
  documented; every layout below them was read off one macOS machine. Both skills now say which
  is which, so a future reader knows which half to distrust.
- **Migrating append-only documents: rewrite pointers, not prose.** During the rename only
  `PREDECESSOR`, `PRIME` and `## Start here` commands were updated — the things that break if
  stale. Narrative was left alone and each file notes what was touched.
- **`${CLAUDE_PLUGIN_ROOT}` is real and correct under Claude Code**, substituted into skill
  content at load time. It is not a shell variable. Do not "fix" it again on the assumption that
  an empty `echo $CLAUDE_PLUGIN_ROOT` proves it broken — that was checked this session.

## Traps

- **Claude Code substitutes `${CLAUDE_PLUGIN_ROOT}` inside your own documentation of it.** You
  cannot write the token in skill prose to explain it. This is currently mangling `SKILL.md:29`.
- **`json.dumps()` is not the file.** While verifying the codex `grep` pattern I read a record
  back through Python and "fixed" the pattern to include a space after the colon, based on
  Python's re-serialization. The rollout files are compact JSON. The shipped pattern is the
  compact one and it was re-verified against real files.
- **The plugin cache is not your working tree.** The skill's base directory is
  `~/.claude/plugins/cache/john-claude-skills/john-skills/<version>/`. Iterating on `gather.sh`
  and invoking the skill tests the *old* script. Invoke the tree copy by path.
- **`$CLAUDE_CODE_SESSION_ID` is inherited by every subshell**, so testing another harness's
  detection from inside Claude Code needs `env -u CLAUDE_CODE_SESSION_ID`.
- **opencode's message record holds no text** in either layout — it lives in a separate `part`
  (`part.data` in the DB, `storage/part/<msg_id>/prt_*.json` on disk). Reading only the message
  tree returns metadata and looks like an empty session.
- **Grok's `chat_history.jsonl` has no `role` field.** Records key on `type`
  (`user`/`assistant`/`reasoning`/`tool_result`); the reasoning ones are encrypted.
- **Amp's synced thread store lags a live session badly** — the newest `threads/T-*.json` can be
  months old while a thread runs. A live thread exists only as a cache log with no model in it.
