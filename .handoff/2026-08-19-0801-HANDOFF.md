## Decisions and rules

- **A handoff recommends; it does not direct.** The user's objection: a handoff agent has one
  session of context, so a bare `NEXT_ACTION` gets obeyed by whoever picks up the work and
  quietly steers an orchestrator who may have decided to go somewhere else entirely. Stripe
  feature this session, security hardening next session — the writing agent can't know.
- **But recommendations stay,** especially for unfinished in-scope work, where the session that
  did the work genuinely knows best. The resolution: the neutral inventory (`## Open threads`,
  `OPEN_LOOPS`) is kept *separable* from the opinion (`## Recommended next`,
  `RECOMMENDED_NEXT`), and the recommendation must carry its reasoning and the consequence of
  skipping it, so it can be overruled on the merits.
- **Surfacing is session-recap's job.** recap must always relay `RECOMMENDED_NEXT`, always
  attribute it to the previous session, never restate it as its own conclusion, and never begin
  executing it. The orchestrator decides.
- **`SCOPE_COMPLETE` exists to weight the recommendation** — `false` means in-scope work went
  unfinished, which is the case where the previous session's view deserves the most weight.
- **Anything the user actually said outranks the agent's recommendation** (`## Stated
  direction`), and both skills say to name the conflict rather than resolve it silently.
- **`HEAD_SHA` is the load-bearing field.** It's what makes the two skills a system instead of
  two documents: recap diffs against it to find what moved after the handoff was written.
- **Handoffs are committed to the repo,** per the user's choice, so the skill forbids secrets
  and says to reference where a value lives instead.
- **Filenames use `YYYY-MM-DD-HHMM`,** hyphen not space — the user's original spec had a space
  and a colon; both were dropped for shell-safety. Lexical sort is chronological, which
  `ls | sort | tail -1` depends on. Don't change the format without fixing both skills.

## Traps

- **`ls .handoff/*-HANDOFF.md | sort | tail -1` is load-bearing in both skills.** It only works
  because the timestamp format sorts lexically. A format change silently breaks predecessor
  detection — it won't error, it'll just pick the wrong file.
- **The repo's pre-commit hook auto-bumps patch versions** for any `plugins/<name>/` change, and
  skips the bump if the staged version already differs from HEAD. A hand-bump is respected; two
  hand-bumps in one commit are not additive. Check `plugin.json` after committing.
- **Claude Code only re-syncs an installed plugin when the version changes** — a content edit
  without a bump never reaches installed copies. This is why the hook exists; don't defeat it.
- `[ -f a ] || [ -f b ] && echo x` bit me in `gather.sh` and was rewritten as a proper `if`.
  Precedence there is not what it looks like.
