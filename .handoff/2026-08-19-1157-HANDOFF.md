## Decisions and rules

- **Repo matching is strict: a session counts only if its cwd IS the repo or sits inside it.**
  The first implementation matched either direction, so a codex/amp/opencode session opened at
  `$HOME` "contained" this repo and all three were falsely reported as having touched it. A
  false "another agent was working here" claim in a handoff is worse than a miss, because the
  next session acts on it. The loose bidirectional check survives as `related()` and is used
  only to decide whether to *warn* that the active session's cwd looks wrong — launching an
  agent at a parent directory and cd'ing in is normal and should not warn.
- **A workspace-verified session always outranks an unverified one when inferring.** Sorting by
  recency alone let Amp's unverified `lastThreadId` fallback beat a codex session with a
  confirmed cwd match. Sort key is `(verified, when)`, and unverified rows carry
  `[workspace unverified — may be another repo]` in the output. Do not simplify that back to a
  recency sort.
- **Env detection takes the first candidate that actually has a session record**, not simply the
  first env var present. Agents nest: a codex run started from a Claude Code shell inherits
  `$CLAUDE_CODE_SESSION_ID` and would otherwise always self-report as claude-code. When more
  than one harness's env is set, the script prints an `ambiguous:` line rather than hiding it.
- **`effort` and `mode` are different fields.** Amp's `agentMode` (smart/medium/fast) is the
  model-tier selector, so it maps to `effort` with an `(amp agent mode)` label. opencode's
  `agent` and grok's `agent_name` are named agent configurations, not effort — they print as
  `mode` with a `mode_kind` label naming their own harness.
- **Everything stays in one bash file** with python3 in a heredoc, matching how the script was
  already written. A separate `.py` would be cleaner but changes the distribution shape.
- **`python3` is now a hard dependency for the SESSION block only.** The script prints a
  degradation notice and continues; every other section is pure shell.

## Traps

- **You cannot test harness detection from inside Claude Code without unsetting its env var.**
  `$CLAUDE_CODE_SESSION_ID` is inherited by every subshell, so `cd ~/scratch/codex && bash
  gather.sh` reports `claude-code`. Use `env -u CLAUDE_CODE_SESSION_ID`. This burned a test
  cycle and made a working codex probe look broken.
- **`/handoff` runs the cached plugin, not your working tree.** The skill's base directory is
  `~/.claude/plugins/cache/john-claude-skills/john-skills/<version>/`. While iterating on
  `gather.sh`, always invoke the tree copy by path or you will silently test the old script.
- **Amp's local thread store lags the live session.** The newest file in
  `~/.local/share/amp/threads/` was four months old while a thread was actively running. Do not
  conclude from that directory that amp is unused.
- **Grok's session directory name is the percent-encoded absolute cwd**
  (`%2FUsers%2F…`). The script matches by `unquote()`ing the directory name and by reading
  `summary.json`'s `info.cwd`; do not try to construct the encoded name by hand.
- **Codex rollouts are not keyed by cwd** — the path is date-based, and cwd lives in the
  `session_meta` line. Any matching requires opening files.
- **Codex's older rollout format uses `payload.id`, the newer one `payload.session_id`**, and the
  2025-era files have no model on `session_meta` at all. Both eras carry
  `turn_context.payload.model`, which is why extraction keys off that.
- **`strings` on a Bun-compiled binary (opencode) finds almost nothing** — the JS is bundled and
  compressed. It worked fine on the Rust/Go binaries (codex, amp, grok). Absence of a hit there
  is not evidence the env var does not exist.
